# Project Charter

## Mission
Help users organize, execute, and reflect on meaningful work — turning intentions into consistent, visible progress.

## Vision
Build an evolving personal system that connects **planning → action → reflection → continuous improvement**, so that every cycle makes the next one better.

## Core Principles

| # | Principle | Why it matters |
|---|-----------|-----------------|
| 1 | **Progress over perfection** | Momentum compounds; polish can wait. |
| 2 | **Every completed task produces knowledge or progress** | Work that teaches nothing is wasted effort. |
| 3 | **Failures are recorded, not hidden** | Mistakes are data — hiding them removes the ability to learn. |
| 4 | **Features must solve real problems** | No speculative complexity; build against actual friction. |
| 5 | **The system stays understandable and maintainable** | A system no one can reason about eventually gets abandoned. |
| 6 | **Complexity is earned, not assumed** | Add it only when the value it unlocks is proven. |

## How This Charter Is Used
- New features are checked against the Core Principles before being scoped.
- Retrospectives reference this document to evaluate whether the system is still aligned with its Mission and Vision.
- Any principle can be revised, but changes should be deliberate and logged (see `docs/objectives`).
